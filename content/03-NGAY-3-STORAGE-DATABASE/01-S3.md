# Amazon S3 — Object Storage

## 1. Data model

```text
AWS account
└── Bucket (Region, globally unique name/namespace rules)
    ├── Object key: photos/2026/a.jpg
    ├── Object data
    ├── Metadata/tags
    └── Version ID nếu bật versioning
```

- S3 là object storage truy cập qua API/HTTP.
- Không phải block disk và không phải POSIX file system.
- “Folders” trong console là prefixes trong object key namespace.
- Bucket được tạo trong một Region; bucket name theo global namespace rules hiện hành.

## 2. Consistency và durability

- S3 cung cấp strong read-after-write consistency cho PUT/overwrite/DELETE và LIST theo service behavior hiện hành.
- Durability và availability khác nhau:
  - durability: xác suất dữ liệu còn nguyên;
  - availability: service có phản hồi request tại thời điểm cần hay không.
- Multi-AZ storage class chịu mất một AZ; One Zone class không.

Không dùng S3 replication như cách “làm S3 consistent”; replication giải geographic copy/compliance/DR.

## 3. Storage classes

| Class | Access latency | AZ | Minimum duration chính | Use case |
|---|---|---:|---:|---|
| Standard | Millisecond | ≥3 | Không | Frequently accessed, primary data |
| Intelligent-Tiering | Millisecond | ≥3 | Không cho frequent tier; archive tiers có rules riêng | Unknown/changing access pattern |
| Standard-IA | Millisecond + retrieval | ≥3 | 30 ngày | Long-lived, infrequent, cần multi-AZ |
| One Zone-IA | Millisecond + retrieval | 1 | 30 ngày | Re-creatable/secondary data |
| Glacier Instant Retrieval | Millisecond + retrieval | ≥3 | 90 ngày | Archive đọc hiếm nhưng cần tức thì |
| Glacier Flexible Retrieval | Phút–giờ | ≥3 | 90 ngày | Archive đọc rất hiếm |
| Glacier Deep Archive | Giờ | ≥3 | 180 ngày | Long-term archive rẻ nhất |
| S3 Express One Zone | Single-digit ms | 1 | Theo class hiện hành | High-request/latency-sensitive trong một AZ |

### Intelligent-Tiering reasoning

Chọn khi:

- không biết access pattern;
- object sống đủ lâu;
- muốn tự động chuyển giữa access tiers;
- tránh retrieval charge của các automatic access tiers theo current pricing model.

Cân nhắc:

- monitoring/automation fee per eligible object;
- object nhỏ có behavior/tiering rules riêng;
- archive access tiers có restore/activation behavior.

### One Zone-IA

Chỉ chọn cho:

- derived data có thể tính lại;
- secondary replica;
- backups khác đã tồn tại;
- use case chấp nhận mất AZ.

Không chọn làm bản duy nhất của data không thể tạo lại.

## 4. Lifecycle rules

Lifecycle actions:

- transition current versions;
- transition noncurrent versions;
- expire current versions;
- permanently delete noncurrent versions;
- remove expired delete markers;
- abort incomplete multipart uploads.

Filter theo prefix, tag, object size và rule criteria được hỗ trợ.

### Design example

```text
Day 0: S3 Standard
Day 30: Standard-IA
Day 90: Glacier Flexible Retrieval
Year 7: expire
```

Phải xét minimum storage duration và retrieval cost. Transition object nhỏ/ngắn hạn có thể đắt hơn để Standard.

## 5. Versioning

- Enabled: mỗi write tạo version ID mới.
- DELETE không version ID tạo delete marker; previous version vẫn tồn tại.
- Delete một version ID xóa version cụ thể.
- Suspended không xóa versions cũ; behavior với null version cần hiểu nhưng ít khi là trọng tâm.
- Lifecycle quản current và noncurrent versions riêng.

Versioning bảo vệ overwrite/delete nhầm, nhưng tăng storage cost. Kết hợp lifecycle để dọn noncurrent versions theo retention.

## 6. Object Lock

- WORM: write once, read many.
- Cần versioning.
- Retention period hoặc legal hold.

| Mode | Behavior |
|---|---|
| Governance | User có quyền bypass đặc biệt có thể thay/xóa |
| Compliance | Không ai, kể cả root, rút ngắn/xóa protected version trong retention period |

Object Lock không mã hóa data; vẫn cần SSE/access controls.

## 7. Replication

### Live replication

- Same-Region Replication (SRR).
- Cross-Region Replication (CRR).
- Asynchronous.
- Source/destination versioning và IAM role/config cần đúng.
- Mặc định tập trung object mới sau khi rule hoạt động.

### Batch Replication

Cho existing objects, failed replicas hoặc on-demand replication jobs.

### Use cases

| Requirement | Replication |
|---|---|
| Compliance geographic copy | CRR |
| Lower read latency gần compute khác Region | CRR |
| Aggregate logs nhiều accounts cùng Region | SRR |
| Separate prod/test/account ownership | SRR/CRR theo location |
| Replicate existing objects | Batch Replication |

### Replication caveats

- Delete behavior cần cấu hình/hiểu; permanent version delete thường không replicate như cách bảo vệ data.
- Lifecycle rules không tự replicate; configure destination lifecycle riêng.
- KMS-encrypted objects cần key permissions/destination encryption design.
- Replication Time Control cung cấp predictable replication SLA cho eligible new objects khi business yêu cầu.

## 8. Upload/download performance

### Multipart upload

- Chia object lớn thành parts.
- Upload song song.
- Retry part riêng.
- Complete request ghép object.
- Nên cân nhắc từ khoảng 100 MB; bắt buộc vượt single-operation threshold theo current S3 limits.
- Lifecycle abort incomplete multipart uploads để tránh cost.

### Byte-range GET

- Tải nhiều ranges song song.
- Resume partial download.
- Tối ưu large objects khi application hỗ trợ.

### Transfer Acceleration

```text
Remote client → nearest edge → AWS backbone → target S3 Region
```

Chọn khi clients xa Region và upload/download qua public internet; test acceleration benefit vì có thêm cost.

### CloudFront

- Cache S3 objects gần viewers.
- Giảm origin requests/data transfer và latency.
- Dùng OAC để giữ bucket private.

## 9. S3 Select, Athena và analytics

- S3 Select/filter use case có lifecycle/support changes; không chọn nếu đề rõ cần SQL query across many objects.
- Athena: serverless SQL query data trong S3.
- Dùng columnar compression (Parquet/ORC), partitioning và file sizing để giảm scanned bytes/cost.
- Glue Data Catalog giữ schema/metadata.

## 10. Event-driven S3

```text
Object created
→ S3 notification/EventBridge
→ SQS/SNS/Lambda/Step Functions target pattern
```

Best practices:

- Consumer idempotent.
- Tránh recursive loop: function ghi lại cùng prefix/bucket và tự kích hoạt.
- SQS buffer nếu spike lớn hoặc downstream chậm.
- EventBridge khi cần richer routing/multiple services.
- CloudTrail data events nếu cần audit object API, không chỉ business event.

## 11. Static website

### S3 website endpoint

- Host static content với index/error document.
- Website endpoint có behavior khác S3 REST endpoint.
- Không cung cấp HTTPS trực tiếp theo classic pattern.
- Public access requirement thường xung đột private-origin best practice.

### Recommended secure global pattern

```text
Route 53 alias
→ CloudFront + ACM + WAF
→ private S3 REST origin via OAC
```

Ưu điểm: HTTPS, cache, custom domain, WAF, bucket private.

## 12. Access Points và Multi-Region Access Points

### S3 Access Point

- Named endpoint/policy riêng cho application/team.
- Có thể giới hạn VPC origin.
- Giảm complexity của một bucket policy lớn.

### Multi-Region Access Point

- Global endpoint cho buckets ở nhiều Regions.
- Route request tới active/optimal Region theo feature behavior.
- Kết hợp replication/failover controls; không tự tạo data replication nếu chưa cấu hình.

## 13. Security summary

- Block Public Access.
- Bucket owner enforced Object Ownership.
- OAC cho CloudFront.
- SSE-S3/SSE-KMS/DSSE-KMS/SSE-C theo requirement.
- TLS enforcement.
- Bucket/access point/VPC endpoint policies.
- CloudTrail data events, access logs/CloudFront logs theo audit.
- Versioning/Object Lock/lifecycle/replication/backup cho data protection.

## 14. Scenario reasoning

### A. Access pattern không biết, object sống nhiều năm

S3 Intelligent-Tiering; tránh tự viết lifecycle dựa trên guess. Xét object size/monitoring fee.

### B. Log không đọc trong 7 năm, restore có thể hàng giờ

Glacier Deep Archive + lifecycle + Object Lock/compliance retention nếu cần WORM.

### C. User toàn cầu upload video vào bucket Australia

Multipart upload + S3 Transfer Acceleration; CloudFront chủ yếu cho download/cache, không thay upload acceleration reasoning.

### D. Existing 10 TB objects phải replicate Region khác

Configure CRR cho new objects + S3 Batch Replication cho existing objects.

### E. Một team chỉ được ghi `team-a/`

IAM/resource policy đúng object prefix và `ListBucket` condition prefix; Access Point riêng có thể đơn giản hóa.

## 15. Exam traps

- S3 “folder” không phải filesystem directory.
- Lifecycle không phải replication.
- CRR live rule không mặc định retroactive cho existing objects.
- Versioning không ngăn authorized permanent version delete; Object Lock/MFA/governance giúp thêm.
- Standard-IA có retrieval/minimum duration/object size economics.
- S3 website endpoint và private OAC REST origin là hai patterns khác nhau.
- Multi-Region Access Point không tự replicate data.
